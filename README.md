# 银行营销文案合规检查工具

一个基于监管规则库的银行 / 理财营销文案风险检查工具。输入营销文案后，先用本地关键词召回命中的监管规则，再由大模型对命中片段做风险定级并给出修改建议；模型不可用时自动降级为本地规则结果。

## 项目简介

银行、理财业务的营销文案受《广告法》《理财公司理财产品销售管理暂行办法》《银行保险机构消费者权益保护管理办法》等法规约束，人工审查成本高且容易漏检。本工具把常用监管条款结构化为规则库，通过「关键词召回 + 大模型判定」两级机制，对文案逐处标记风险，并输出法规依据与修改建议。

法规原文保存在本地规则库中，最终展示的「法规依据」始终来自本地，不会被模型改写，避免出现伪造法条。

## 功能特性

- **本地关键词召回**：命中规则关键词才会进入后续判定，不相关文案不调用模型，节省成本。
- **大模型风险定级**：按高 / 中 / 低三档输出风险，并给出命中原因与修改建议。
- **原文逐字校验**：模型返回的片段必须能在原文中逐字找到，伪造或拼接的片段会被丢弃。
- **规则越权过滤**：模型只能引用本次召回到的规则，其余 `ruleId` 一律忽略。
- **自动降级**：未配置 API Key、模型调用失败或返回为空时，自动回退到本地规则命中结果。
- **结果可视化**：左侧输入、右侧风险卡片，支持高 / 中 / 低计数、命中规则标签与错误提示。

## 快速开始

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（参考 .env.example）
#    Windows PowerShell:
#    Copy-Item .env.example .env.local
#    macOS / Linux:
#    cp .env.example .env.local

# 3. 启动开发服务器
npm run dev
```

打开 <http://localhost:3000>，在左侧输入文案（例如「保证年化收益8%，稳赚不赔」），点击「检查」或按 `Ctrl/⌘ + Enter`。

生产构建：

```bash
npm run build
npm start
```

## 接口说明

### `POST /api/check`

请求体：

```json
{ "text": "保证年化收益8%，稳赚不赔" }
```

响应体（`CheckResponse`）：

```json
{
  "risks": [
    {
      "id": "AD-LAW-25-0",
      "snippet": "保证年化收益8%",
      "level": "高",
      "ruleId": "AD-LAW-25",
      "ruleName": "广告法第二十五条（金融理财广告）",
      "legalBasis": "……",
      "reason": "对未来收益作出保证性承诺",
      "suggestion": "删除“保本/保收益”等承诺性表述……"
    }
  ],
  "matchedRules": [{ "id": "AD-LAW-25", "name": "广告法第二十五条（金融理财广告）", "hits": ["保证年化"] }],
  "source": "ai"
}
```

字段说明：

- `source`：`ai` 表示模型结果，`fallback` 表示本地关键词兜底。
- `notice`：降级或未命中规则时的提示信息。
- `error`：参数校验失败时的错误信息。

约束：文案为空返回 400；文案超过 20000 字返回 400。

## 规则库

规则定义在 [rules.ts](./lib/rules.ts)，每条规则包含 `legalBasis`（法规原文）、`level`（默认风险等级）、`description`（违规要点）、`keywords`（召回关键词）、`suggestion`（兜底建议）。

| 规则 ID | 名称 | 默认等级 |
| --- | --- | --- |
| `AD-LAW-25` | 广告法第二十五条（金融理财广告） | 高 |
| `WM-SALES-23` | 理财公司理财产品销售管理暂行办法第二十三条 | 中 |
| `CONSUMER-PROTECT-21` | 银行保险机构消费者权益保护管理办法第二十一条、第二十二条 | 中 |

新增规则时在 `RULES` 数组中追加对象即可，前后端会自动生效，无需改动其他代码。

## 检查流程

1. 前端把文案 `POST` 到 `/api/check`。
2. 服务端做参数校验（非空、长度 ≤ 20000）。
3. `matchRules` 用本地关键词召回命中规则；未命中则直接返回空结果，不调用模型。
4. 将**命中的规则**拼接进 prompt，调用模型并要求输出 JSON。
5. `normalizeRisks` 校验模型输出：片段必须在原文中存在、`ruleId` 必须在召回结果内、按 `ruleId + snippet` 去重，最多保留 12 条。
6. 模型不可用或结果为空时，用 `buildFallbackRisks` 生成基于本地规则的兜底结果。
7. 前端渲染风险卡片，按高 / 中 / 低汇总计数。

## 已知限制

- 规则库目前仅内置 3 条硬编码规则，覆盖范围有限，仍需人工复核。
- 关键词召回基于字符串包含匹配，不做同义词与语义扩展，可能漏检改写后的表述。
- 未对文案做分句切割，单条风险片段长度以模型输出为准（≤ 40 字）。
